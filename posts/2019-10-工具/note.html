📌 Git / GitHub / GitLab 中的两点对比与三点对比指南

在开发过程中，我们需要频繁查看代码差异。特别是在一次性查看连续提交多个 Commit 后的总变更时，对比（Compare）功能非常高效。

1. Git 分支分支演进图示

A --- B (main 分支最新状态) / --- O (共同祖先 / Merge Base) \ C --- D (feature 特性分支最新状态)

2. 为什么“两点对比”和“三点对比”都是必要的？

对比类型 对比算法逻辑 典型应用场景与必要性
两点对比 (..) 直接将 B 点 和 D 点 的文件快照进行硬对比（相当于 diff(B, D)）。 【绝对状态对比】
适用于：同一分支对比多个 Commit 增量、或者只关心“此刻这两个版本文件代码物理上有何不同”。
缺点：对比不同分支时，主干新合并的代码（A、B）会被错当成“被删除的代码”。
三点对比 (...) 先找到共同祖先 O 点，再对比 O 点 与 D 点 的差异（相当于 diff(O, D)）。 【代码评审 / PR / MR】
适用于：分支合并前 Review 代码。
优势：自动过滤掉主干分支后来演进的代码（A、B），让评审者只聚焦于该特性分支自身独立贡献的代码（C、D）。

3. GitHub 与 GitLab Compare 功能的 URL 格式

🐙 GitHub

  • 三点对比 (默认 PR 逻辑):
    https://github.com/<owner>/<repo>/compare/<from_commit>...<to_commit>
  • 两点对比 (直接对强撞物理差异):
    https://github.com/<owner>/<repo>/compare/<from_commit>..<to_commit>

🦊 GitLab

  • 默认 Compare 逻辑 (3-dot):
    https://gitlab.com/<owner>/<repo>/-/compare/<from_commit>...<to_commit>
  • 说明与切换:
    GitLab 的 URL 同样遵循此标准。如果因 3-dot 导致页面显示 "There are no changes"，可尝试在 UI 的设置下拉菜单中更改 Diff 模式，或者直接把 URL 中的 ... 手动改成 ..。
💡 总结技巧：
  • 如果要看 “一个分支合并会带来什么变化” ➔ 用 三点对比 ...。
  • 如果要看 “任意两个 Commit 节点之间代码有什么不同” ➔ 用 两点对比 ..。
